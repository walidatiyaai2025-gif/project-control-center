# Rollback, Production Verification and Incident Management

Every release with meaningful production risk must define a rollback or forward-fix decision path before deployment. Production verification must validate the deployed artifact/source identity and critical smoke checks.

Incidents receive an incident ID, severity, start/detection times, affected project/release/SHA, containment, evidence, owner, current state, resolution, and follow-up tasks. Incident fixes still require canonical Task IDs; emergency handling shortens lead time, not traceability.
