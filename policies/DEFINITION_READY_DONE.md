# Definition of Ready / Definition of Done

## Definition of Ready

A task is READY only when it has: canonical Task ID; requirement/source request; duplicate check; project ID; intended base lineage; canonical task branch name or creation plan; scope and non-scope; acceptance criteria; risk/dependencies; required validation; and an identified escalation path for blockers.

## Definition of Done

DONE is terminal and evidence-based. Required evidence must include, when applicable: implementation commit SHA; PR; CI result at exact SHA; QA result; integration SHA; release/build identity; production verification; documentation/migration evidence; and user acceptance/delivery state.

`READY_FOR_QA`, `QA_PASS`, `INTEGRATED`, and `RELEASED` are not synonyms for DONE.
